1. The real request

The server resolves the exact Tokenized Assets category, paginates every entry, and ranks fresh, positive USD market caps. A key, when configured, stays on the server.

const origin = key
  ? 'https://pro-api.coinmarketcap.com'
  : 'https://pro-api.coinmarketcap.com/public-api';
const response = await fetch(`${origin}/v1/cryptocurrency/categories?limit=5000`, {
  headers: { Accept: 'application/json',
    ...(key ? { 'X-CMC_PRO_API_KEY': key } : {}) }
});
// Resolve category.id, then paginate:
// /v1/cryptocurrency/category?id=...&start=1&limit=1000&convert=USD
// Never send the credential to the browser.

What the API made possible
Stable CMC IDs connect the market ranking to researched passports. Category pagination makes the denominator explicit and lets newly listed assets appear without fabricated research.
What got in the way
Category membership and market capitalization do not explain legal rights, reserve provenance or custody precision. Those require separate issuer and public-data sources. Rate limits and pagination require caching, cooldowns, freshness checks and a clear partial-coverage label.
The selected track is Data and Visualisation. The demo does not claim integration with the separate v5 underlying-RWA endpoint family.
